# Server-Side Tracking

Server-side tracking is the process of receiving, validating, processing, and storing user activity events on the backend.

While the client detects the user's actions, the server is responsible for handling the events safely.

## How It Works

```text
Client
  ↓
Tracking Event
  ↓
Backend API
  ↓
Validate Event
  ↓
Process Event
  ↓
Store Event
```

## Receiving Events

The client can send an event to a backend endpoint:

```text
POST /api/events
```

For example:

```json
{
  "event": "product_viewed",
  "data": {
    "product_id": "123"
  }
}
```

The server receives this request and processes the event.

## Validating Events

Never assume that data received from the client is valid.

The server should validate things such as:

* Event name
* Required fields
* Data types
* Payload size
* Allowed values

For example, an event should not be accepted if a required `product_id` is missing.

## Processing Events

After validation, the server can add information or perform additional processing.

For example:

```text
Client Event
     ↓
Validate
     ↓
Add timestamp
     ↓
Identify session
     ↓
Store
```

Server-side processing can also be used to handle business-related events that should not depend entirely on the client.

For example:

```text
payment_confirmed
order_completed
subscription_created
```

These events can be generated by the backend after the corresponding action has actually been completed.

## Storing Events

After processing, the event can be stored in a database or another storage system.

A stored event might look like:

```json
{
  "event": "product_viewed",
  "product_id": "123",
  "session_id": "abc123",
  "timestamp": "2026-10-08T10:00:00Z"
}
```

The stored data can later be used for analytics and reporting.

## Security Considerations

The tracking endpoint is a public-facing endpoint, so it should be treated as untrusted input.

Consider implementing:

* Input validation
* Rate limiting
* Payload size limits
* Authentication where appropriate
* Data sanitization
* HTTPS
* Access control

Do not trust client-provided data simply because it came from your own application.

## Client + Server Tracking

A complete tracking system can use both client-side and server-side tracking:

```text
        User Action
             ↓
        Client Tracker
             ↓
        Tracking API
             ↓
        Server Validation
             ↓
       Event Processing
             ↓
          Storage
             ↓
         Analytics
```

The client is responsible for **detecting activity**, while the server is responsible for **processing and safely storing the resulting events**.
