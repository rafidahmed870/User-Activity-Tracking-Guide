# Client-Side Tracking

Client-side tracking means detecting user activities directly in the user's browser or application.

The client is responsible for detecting an action and creating an event before sending it to the backend.

## How It Works

```text
User Action
    ↓
Browser Detects Action
    ↓
Create Event
    ↓
Send Event to Backend
```

For example, when a user clicks a button:

```text
User clicks button
       ↓
Click detected
       ↓
"button_click" event created
       ↓
Event sent to API
```

## Detecting User Actions

A client-side tracker can listen for different types of interactions, such as:

```text
Click
Page View
Form Submit
Scroll
Search
Navigation
```

For example:

```javascript
button.addEventListener("click", () => {
    track("button_click");
});
```

The `track()` function can be responsible for creating and sending the event.

## Sending Events

Once an event is created, it can be sent to the backend through an API.

```javascript
track("product_viewed", {
    product_id: "123"
});
```

The client can then send the event to an endpoint such as:

```text
POST /api/events
```

The backend receives the event and handles validation, processing, and storage.

## What Should Be Tracked?

Not every interaction needs to be tracked.

Focus on actions that provide useful information about the application, such as:

* Important feature usage
* Conversion-related actions
* Navigation
* User workflows
* Business-specific events

Avoid collecting unnecessary or sensitive information.

## Client-Side vs Server-Side

Client-side tracking is useful for interactions that happen directly in the browser.

Server-side tracking is useful for events that are confirmed or generated by the backend.

For example:

```text
Client:

button_click
product_viewed
page_view


Server:

order_completed
payment_confirmed
subscription_created
```

In many applications, both approaches can be used together.

## Basic Concept

```text
Browser
   ↓
Detect Activity
   ↓
Create Event
   ↓
Send to API
   ↓
Backend
```

Client-side tracking is the first step in collecting user activity. The next step is receiving and processing these events on the server.
